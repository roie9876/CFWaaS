Set up the provider platform

A provider-tenant administrator signs in and approves this one-time setup.

Review before you sign in

This setup requests provider-tenant Microsoft Graph delegated permissions to manage applications and app-role assignments. It then grants these application permissions to the FaaS management identity:

  • Application.ReadWrite.OwnedBy
  • Application.Read.All
  • AppRoleAssignment.ReadWrite.All

These are privileged provider-directory permissions. A suitably authorized Entra administrator must review and approve the Microsoft sign-in prompt. No customer tenant access is requested.

The management app enables ID tokens for App Service's hybrid sign-in flow; implicit access tokens remain disabled.

Complete Microsoft sign-in

Open the Microsoft page, enter this code and sign in using the provider administrator account:

Open Microsoft sign-in

Only enter the code shown on this page. Confirm the application name and requested permissions on Microsoft's sign-in screen.

Create provider setup

Sign-in succeeded. Continue to create the provider API and management identities, grant the listed Graph application permissions, and save the generated management credential and NVA SSH key in the private provider Key Vault.

No secret or private key will be placed in the deployment link. An interrupted or uncertain directory operation stops for review rather than silently creating a duplicate.

Deploy provider platform

The provider identities are prepared. Open the Azure deployment form to select the provider resource groups and create the hosting resources.

Open provider deployment wizard

The link is short-lived and contains read-only artifact access, not an API credential. Deployment creates billable Azure resources.
